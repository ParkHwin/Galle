[후보 5 상세 Q&A]

Q: 이미 있는 거 아닌가?
A: 서울→부산 갈 때 KTX, SRT, 고속버스, 항공, 자가용을 한 화면에서
   가격·시간·편의성으로 비교할 수 있는 한국 서비스가 없다.
   네이버 지도는 도시 내 이동(버스+지하철+자동차)만 비교.
   도시 간 KTX vs 항공 vs 고속버스는 각각 코레일 앱, 네이버 항공권,
   고속버스 앱을 따로 열어서 확인해야 함.

Q: Rome2rio는?
A: Rome2rio는 한국 데이터 부정확. KTX/SRT 구분 안 됨,
   고속버스 노선 불완전, 한국어 미지원, 가격 오차 큼.
   한국 교통 체계 특화 버전이 없다.

Q: 가격 데이터를 API로 정확히 가져올 수 있는가?
A: KTX/SRT → 구간별 고정 요금, 공개 정보. 문제없음.
   고속버스 → 고정 요금. 문제없음.
   항공권 → 동적 프라이싱이라 무료 API로 실시간 가격 어려움.
   → 대응: 항공은 "가격대 범위 + 예매 링크"로 처리.

Q: 무료 API가 진짜 있는가?
A: 공공데이터포털(data.go.kr) 확인 가능:
   - 코레일 열차정보 API
   - 국토교통부 고속버스 노선/운임 API
   - TAGO 대중교통 API
   - 한국공항공사 운항정보 API
   - 인천공항 운항정보 API
   전부 무료 키 발급 가능.

Q: 혼자 만들 수 있는가?
A: MVP를 서울 출발 → 주요 5개 도시(부산, 대전, 대구, 광주, 제주)로
   한정하면 관리 가능. API 4~5개 통합 + 비교 로직 + 프론트엔드. 2~3개월.

Q: 수익화가 되는가?
A: 예매 사이트 어필리에이트 링크. Skyscanner, 네이버 항공권이 쓰는
   모델과 동일 구조. 전환당 수수료.

Q: 누가 쓰는가?
A: 출장족(주 1~2회 도시 간 이동), 주말 여행자,
   귀성길 최적 경로 찾는 사람. 도시 간 이동하는 모든 한국인.

[문제 정의]

서울에서 부산 가려고 할 때 선택지가 5개다:

  교통수단      가격              소요시간         확인 앱/사이트
  ─────────────────────────────────────────────────────────────
  KTX          ~59,800원         2시간 18분       코레일 앱
  SRT          ~52,600원         2시간 15분       SRT 앱
  고속버스      ~23,000원         4시간 20분       고속버스 앱
  항공          40,000~90,000원   1시간(+공항이동)  네이버 항공권
  자가용        톨비+유류비        4~5시간          네이버 지도

→ 비교하려면 앱/사이트 4~5개를 따로 열어야 한다.
→ 한 곳에서 가격·시간·출발시간을 비교할 수 있는 곳이 없다.


[솔루션]

  한 화면에 비교
→ 원하는 옵션 선택하면 해당 예매 사이트로 바로 연결


[사용 API — 전부 무료]

[핵심 공백]

[Rome2rio 한국 실패 원인]
Rome2rio에서 "Seoul to Busan" 검색하면 KTX가 나오긴 하지만,
SRT가 안 나오거나, 가격이 틀리거나, 고속버스 노선이 불완전하다.
한국 교통 체계의 복잡성(KTX vs SRT, 동서울 vs 센트럴시티 vs 고속터미널,
인천공항 vs 김포공항)을 제대로 반영하지 못한다.
로컬 데이터 품질 문제라 글로벌 서비스가 해결하기 어렵다.

[약점 1] 항공권 실시간 가격 확보 문제 ★ 가장 큰 리스크

KTX·SRT·고속버스는 구간별 고정 요금이라 문제없음.
항공권은 동적 프라이싱이고, 항공사가 무료 API로 실시간 가격 미제공.
Skyscanner API(Affiliate)는 승인 절차 까다롭고 개인 프로젝트에 비승인 가능성 높음.

→ 보완:
  MVP에서 항공은 두 가지 전략.
  (a) 항공 노선 존재 여부 + 평균 가격대만 표시
      ("이 구간 항공편 있음, 보통 4~8만원대")
  (b) "최저가 확인하기" 버튼 → 네이버 항공권/스카이스캐너로 딥링크
  ※ 부정확한 가격을 정확한 척 보여주는 것이 가장 위험.
    차라리 "범위"로 표시하는 게 신뢰를 지킨다.


[약점 2] API 응답 속도 + 안정성

5개 API 동시 호출 시 가장 느린 API가 전체 응답 시간 결정.
공공데이터포털 API 응답 2~5초 → 사용자 10초 대기 시 이탈.

→ 보완:
  주요 구간 데이터 주기적 캐싱.
  사용자 요청 시 캐시에서 즉시 응답, 변동 데이터만 실시간 호출.
  캐시 갱신 주기: 고정 요금 → 월 1회, 스케줄 → 일 1회.


[약점 3] 스코프 폭발 위험

"전국 모든 도시 간 모든 교통수단"을 하면 조합 폭발.
기차역 없는 도시, 공항 없는 도시, 직행 버스 없는 구간 등 예외 처리 끝없음.

→ 보완:
  MVP를 서울/수도권 출발 → 부산, 대전, 대구, 광주, 제주 5개 노선 한정.
  이 5개가 한국 도시 간 이동 대부분 커버. 검증 후 확장.


[약점 4] "그냥 네이버에서 각각 검색하면 되잖아"

약지기 때 "약국 DUR이 이미 하잖아"와 같은 구조의 반론.
차이점: 약국 DUR은 자동으로 돌아가지만,
교통수단 비교는 사용자가 수동으로 4~5개 앱을 열어야 한다.
이 수고를 줄이는 것이 가치.
단, 그 가치가 "새 사이트를 기억하고 방문하는 수고"를 넘어서야 한다.

→ 보완:
  첫 사용 경험이 "와, 이거 편하다"여야 함.
  검색 결과 페이지의 정보 밀도와 비교 UX가 핵심.
  서울→부산 검색 한 번에 모든 옵션이 가격순/시간순 정렬.
  이 경험이 약하면 "그냥 네이버에서 검색할게"로 돌아감.


[약점 5] 자가용 비용 계산 정확도

고속도로 톨비는 구간별 상이, 유류비는 유가 따라 변동.
"자가용 약 X원"의 X 정확도 문제.

→ 보완:
  한국도로공사 톨비 API + 평균 연비 기반 유류비 추정.
  "예상 비용"임을 명시. 차종별 옵션(경차/중형/SUV) 제공.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Phase 1: MVP 빌드 — 1.5~2개월]

- 서울 출발 → 5대 도시
- KTX + SRT + 고속버스 + 자가용 비교 (항공은 v1.5)
- 핵심 화면: 검색 → 결과 비교 → 예매 링크
- 본인 + 주변 10명 실사용 테스트
- 핵심 질문: "이거 쓰고 나서도 코레일 앱 따로 열었나?"


[Phase 2: 배포 + 초기 유입 — 2~3개월]

- 에브리타임: "서울↔부산 KTX vs SRT vs 버스 가격 비교 사이트 만들었습니다"
  → 대학생 귀성길 시즌(설/추석/방학)에 맞추면 바이럴 가능성
- 디스콰이엇: 사이드 프로젝트 커뮤니티 노출
- SEO 블로그: "서울 부산 KTX 가격", "서울 제주 비행기 vs 배" 등
  실제 검색 키워드 타겟 (검색량 이미 높음)
- 추석/설 시즌 공략: 귀성길 교통 비교는 매년 반복되는 시즌 이슈.
  시즌 2주 전 배포하면 타이밍 최적.


[Phase 3: 확장 — 4개월~]

- 항공 가격대 추가
- 전국 도시 간 확장
- 가격 알림 기능 ("이 구간 최저가 갱신 시 알림")
- 모바일 최적화 / PWA


[핵심 채널 우선순위]
SEO > 에브리타임 > 디스콰이엇
"서울 부산 교통비"를 검색하는 사람이 이미 있다.
그 검색을 잡는 게 가장 효율적.

 /monetize — 수익 모델
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Tier 1 — 어필리에이트 링크 (Day 1부터 가능)]

- 사용자가 "KTX 예매하기" 클릭 → 코레일 예매 페이지 이동
- 항공편 "최저가 확인" → 네이버 항공권/스카이스캐너 이동
- 전환당 수수료 또는 CPC 기반
- ※ 현실 체크: 코레일/SRT 어필리에이트 프로그램 운영 여부 확인 필요.
  없으면 항공 쪽(스카이스캐너 어필리에이트)부터 시작.


[Tier 2 — 가격 알림 프리미엄 (사용자 확보 후)]

- 무료: 기본 비교 검색
- 월 1,900원: 특정 구간 가격 알림, 검색 이력 저장, 즐겨찾기
- 출장 잦은 직장인이 타겟


[Tier 3 — 광고 (트래픽 확보 후)]

- 검색 결과 페이지 상단에 교통 관련 광고 (렌터카, 숙소 등)
- 일일 방문자 1,000+ 이후 의미 있는 수준


[현실적 수익 예측]

- 월 10,000 방문자 × 30% 클릭률 × 100원/클릭 = 월 30만원 (Tier 1)
- 작지만 대학생 사이드 프로젝트로는 유의미
- 수익이 발생한다는 사실 자체가 포트폴리오 차별화 요소

 /retention — 리텐션 전략
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[구조적 강점]
"도시 간 이동이 발생할 때마다" 사용.
완전한 일상 도구는 아니지만 대체제가 없다.


[리텐션 장치]

1. 시즌 트리거 (가장 강력)
   - 설·추석 귀성길, 여름 휴가, 주말 여행 시즌
   - 매년 반복되는 시즌 트래픽
   - SEO로 잡으면 연중 유입 발생
   - "귀성길 교통 비교"는 매년 검색량 급증 키워드

2. 가격 알림
   - "서울→부산 KTX 특가 나오면 알림" → 재방문 트리거
   - 항공권 가격 변동 알림
   - 이메일 또는 웹 푸시

3. 자주 가는 경로 저장
   - "내 경로: 서울↔부산, 서울↔대전" 즐겨찾기
   - 열면 바로 내 경로 최신 비교 표시
   - 검색 없이 결과 확인

4. 검색 이력 기반 추천
   - "지난주 서울→대전 검색하셨죠. 이번 주 KTX 가격이 변동되었습니다"


[리텐션 평가]

DAU 기준으로는 날씨 앱만큼 높을 수 없음.
핵심 지표는 MAU(월간)와 시즌 피크.
이 서비스의 리텐션 구조는 "습관"이 아니라 "필요할 때 떠오르는 도구".
가위가 필요할 때 가위를 찾는 것과 같음.
리텐션은 브랜드 인지도와 SEO 순위가 결정.
"서울 부산 교통 비교" 검색 시 1페이지에 나오면 리텐션 문제 자동 해결.


[가장 큰 리텐션 리스크]
네이버나 카카오가 똑같은 기능을 지도 앱에 추가하면 끝.
모든 사이드 프로젝트가 안고 있는 플랫폼 리스크.
대기업이 추가하기 전까지 선점하는 것이 전략.

[핵심 강점 3가지]

1. 경쟁자가 정확히 0이다.
   한국에서 도시 간 멀티모달 교통 비교 서비스 없음.
   "이미 해결된 문제" 함정을 피함.

2. 수익 모델이 검증된 구조다.
   어필리에이트/딥링크는 Skyscanner가 수조 원 규모로 운영하는 모델.
   규모만 다를 뿐 구조는 동일.

3. 시즌 트래픽이 보장된다.
   "서울 부산 KTX 가격"은 매년 수만 건 검색되는 키워드.
   SEO만 잡으면 마케팅 비용 0으로 유입.


[최우선 실행 항목]

1. data.go.kr에서 코레일 열차정보 API와 고속버스 운행정보 API를
   직접 호출해서 응답 데이터 구조 확인.
   특히 가격 데이터 포함 여부, 특정 날짜/시간대 스케줄 조회 가능 여부.

2. 이 두 가지가 안 되면 설계를 수정해야 한다.
